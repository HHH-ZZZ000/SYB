# 自然语言助手

## 使用

重启当前 Flask 服务（关闭旧 `run.bat` 服务窗口后重新运行），刷新网页，在侧栏打开 **智能助手**，地址为 `http://127.0.0.1:5000/#/assistant`。

1. 在“本次设备”中明确选择设备，或在对话里提供完整设备 ID。助手不会自动选择列表第一项，即使目前只有一台设备。
2. 输入“查看上次数据”“看看刚才采集的结果”“查询今天的历史数据”等读取已有记录。
3. 输入“重新采集一次”“现在再采一遍”“获取最新数据”创建一次新的任务。
4. 缺少参数时，直接回答澄清问题，例如 `ESP32-S3-EYE`；已确认的设备会用于后续对话。选择下拉设备后也可回复“确认”。
5. 请求处理中可取消或发送新请求替换当前交互。新采集先读取 `/api/latest` 的真实在线状态，明确离线时直接提示且不创建任务。在线时创建任务，等待回执最多 6 秒；首次收到 `RUNNING` 后留出 8 秒采集窗口，后续轮询不会续期。未完成且未取消/替换时保留任务编号，可点击“继续查询本次任务”。切换模块不会重发采集；刷新后仅提供未取消任务的查询入口。

等待策略依据：固件 `COMMAND_INTERVAL_MS=1000`，命令 HTTP 超时 1500 ms，因此无回执预算为三次正常轮询间隔加两次网络请求余量（6 秒）；固件单次采样期限 5 秒，加两次网络请求余量得到执行窗口 8 秒。从开始轮询算，无回执约 6 秒、已执行但未完成最多约 14 秒结束本轮等待。解析、在线预检查和创建任务的请求耗时另计，仍保留原接口每次 4 秒超时。后端 `SENT` 30 秒、`RUNNING` 60 秒及每 5 秒扫描机制不变；前端短等待不取消任务，也不将其改为后端超时状态。

等待反馈依次为检查设备、创建任务、等待 ESP32 响应或设备采集中，并显示轮询阶段已经过的秒数。文字和识别文本仍共用 `AssistantSession.send()`；TTS 继续只读最终结果。

2026-09-28 等待策略定向验证：`node --test tests/test_assistant.mjs tests/test_assistant_voice.mjs` 共 36 项通过，覆盖离线不创建任务、在线任务关联、无响应 6 秒预算、执行窗口不续期、请求截止中止、语音/文字离线结果一致和历史查询。6 秒/8 秒边界采用可控时钟测试，语音采用事件替身；不代表真人或在线硬件验收。真实后端当前离线状态下，`AssistantSession.send()` 完整请求实测 106–107 ms 返回，创建任务请求数为 0；浏览器也显示离线提示。设备接回后的串口仍报告 `ESP_ERR_HTTP_CONNECT`，本次未测得在线真实采集耗时，也未完成真实设备任务发出后断连测试。

示例按钮只填入输入框，**发送请求**才执行。所有结果使用真实接口返回的设备、记录编号、原始采样时间、服务器接收时间和来源。实时设备状态与历史记录的时间分别展示。

## 第六周：当前请求与取消

- 每轮交互分配独立 UUID `request_id`，由 `currentRequestId` 确定当前控制权。请求记录保存文本、创建时间、状态、取消/失效标记及 `task_id`；只保留最近 20 条请求管理记录。结果卡片的“详细信息”显示交互请求编号，任务编号仍单独显示。
- 后端既有协议的 `request_id` 实际是采集任务编号，不改协议或真实性校验。助手在边界将工具的 `requestId` 映射为 `task_id`，不会拿交互编号查采集结果。
- 只向原解析接口传当前设备和一份待补齐参数；补充设备名继续该待完成意图，不创建额外业务任务。各轮交互仍有独立编号，`context_from` 记录参数上下文来源。成功、失败、取消或新的明确任务会清除旧待补齐上下文，设备选择作为当前设置保留，不传整段聊天历史。
- 文字/语音“取消”“算了”“停止这个任务”“取消当前任务”，或页面取消按钮，均由 `send()` 进入同一取消逻辑。当前编号失效，HTTP 等待与轮询停止，TTS 停止，清除澄清和恢复入口。后台没有取消任务 API：设备可能继续执行并保存数据，不能宣称物理取消。创建接口尚未返回时也按可能已提交处理，绝不自动重发。
- 每次异步请求前后、结果呈现与 TTS 回调均核对当前请求身份。被替换/取消请求的迟到结果不会改页面状态、参数上下文、恢复入口或声音；迟到的创建响应如提供任务编号，只关联到旧请求审计记录。
- 顶部“停止播报”或输入“停止播报”只调用原 `speechSynthesis.cancel()`，不删除文字、不取消查询/采集。当前播放恢复 idle，旧播放事件不影响下一条播报。页面保留原布局，等待时允许继续文字输入或按键说话。
- `session.events` 是最多 30 条的内存事件日志，含 request_id、task_id、状态、cancelled/stale；只记创建、替换、取消、关联任务、迟到忽略和停止播报，不记敏感数据或每次轮询。

定向测试：`node --test tests/test_assistant_requests.mjs tests/test_assistant.mjs tests/test_assistant_voice.mjs`，44 项通过。覆盖短期补参、取消轮询、创建响应迟到、旧任务成功迟到、A/B 乱序、停止播报与继续请求、语音控制词、第四/第五周查询采集与真实结果校验。使用隔离 HTTP 数据库、模拟设备和浏览器音频事件替身；不代表真人语音或真实 ESP32 验收。

浏览器隔离页面实测：请求等待期间输入框仍可用；取消按钮立即显示取消状态，旧响应到达后未恢复结果；随后文字查询正常完成。实际点击“播报最新回答 → 停止播报”，页面显示播报已停止，查询文字保持不变。未以听感确认扬声器停止，未进行真人 ASR 或真实设备取消后继续上传验收。

## 第五周：按键说话与语音播报

语音入口在原“智能助手”页内。**音频来源为电脑/浏览器麦克风，运行位置为 Web 端**，没有使用或修改 ESP32 音频硬件。文字入口继续独立工作。

1. 正常进入现有 Web 系统并打开“智能助手”，选择设备。后端识别到直接来自本机的 HTTP 网页访问时，会在同一标签自动使用 localhost 安全入口，保留原路由；无需手动复制地址。仅网页入口会跳转，ESP32 的局域网接口地址不变。
2. 点击“开始说话”，允许麦克风；页面确认“正在录音”后说出请求，再点击“结束说话”。浏览器可能在一句话结束时自动停止；录音最多 30 秒，不自动重启监听。
3. “识别文字”展示原始识别内容；仅收到最终识别结果并结束监听后，才自动进入原助手处理。临时结果、无声、权限拒绝、启动或识别超时均不提交任务。
4. 最终回答仍显示在对话中。默认自动播报，可取消勾选；“语音说明”中保留“播报最新回答”“停止播报”。浏览器阻止自动播放时可手动重试。TTS 失败不改变任务结果。

### 入口和滚动定向修复

启动方式仍是 `run.bat`，入口修复需要重启后端。当前部署使用同一电脑访问，因此采用浏览器认可的 loopback 入口，没有生成自签证书、安装信任根或关闭浏览器保护。来自其他电脑或带代理转发头的访问不会重定向到 localhost；跨电脑语音访问仍需管理员提供有效、被客户端信任的 HTTPS 部署，本次未配置或验证远程 HTTPS。

原对话区同时存在页面滚动和 `max-height:58vh; overflow-y:auto; overscroll-behavior:contain` 内层滚动，内层到边界会阻断外层滚动。现由页面统一纵向滚动，卡片、任务编号和表格不限制纵向高度；仅在页面原本接近底部时跟随新消息，查看历史时保留位置。输入框处于正常文档流，不覆盖结果。

页面按“设备 → 快捷操作 → 紧凑语音栏 → 对话 → 输入框”排列，语音说明默认收起；结果原文、状态、采样时间与任务编号保留，来源和服务器接收时间放在“详细信息”。未更改 `AssistantSession.send()`、查询/采集接口或固件。

## 本地意图解析范围与配置

项目未发现已配置的授权语言模型服务或密钥。本次采用可审计的本地规则解析，返回结构化 `query_existing` / `collect_new` 意图和参数；不冒充通用大模型，也不训练模型或把对话传到外部服务。无法确定的请求返回澄清问题，不以猜测执行采集。

- 支持设备 ID、默认板卡已有显示名 `ESP32-S3-EYE`、显式配置的设备别名。
- 支持三轴加速度；其他数据类型、位置筛选、批量/定时采集没有对应的既有工具，明确要求澄清。
- 历史时间按北京时间、服务器接收时间筛选。支持 `YYYY-MM-DD`、日期/时间范围（例如 `2026-09-24 09:00 到 2026-09-24 18:00`）、今天/昨天/前天、最近 N 分钟/小时/天，以及最近 N 条（1–100 条）。
- “刚才的数据”读取已有记录；“刚才采集的结果”优先读取本对话已知任务，否则查询已有的最近任务。不会创建任务。
- 单独的“采集数据”、多个设备、同时查询和采集、缺少日期的“下午”等表达会澄清。

“1号设备”没有天然对应关系。确有这个映射时，可在启动服务的 PowerShell 窗口明确配置，再运行 `run.bat`：

```powershell
$env:IMU_ASSISTANT_DEVICE_ALIASES = '{"1号设备":"ESP32_S3_EYE"}'
.\run.bat
```

配置指向的 ID 必须出现在真实 `/api/devices` 结果中；不能以别名凭空创建设备。没有配置时，“1号设备”会提示用户提供实际 ID。测试使用隔离配置中的别名，不改变正式环境。

## 最小集成与真实性边界

新增 `POST /api/assistant/interpret` 只读取已有设备列表，返回解析结果，不创建任务、不写入传感器数据、不执行任意命令。

```json
{"message":"查看上次数据","context":{"device":"ESP32_S3_EYE","pending":null}}
```

前端受限工具位于 `web/services/assistantTools.js`，只使用固定接口：

| 工具 | 复用接口 | 行为 |
| --- | --- | --- |
| `query_existing_data` | `/api/devices`、`/api/latest`、`/api/records`、`/api/task/latest`、`/api/task/<id>` | 仅 GET，保留已有记录时间 |
| `collect_new_data` | `/api/devices`、`/api/latest`、`POST /api/task/create` | 先校验设备和采集前记录编号；一次 POST，不自动重发 |
| `wait_for_collection` | `GET /api/task/<本次任务编号>` | 等待真实终态；失败或超时不返回虚构样本 |

只有任务状态为 `SUCCESS`，且任务编号、设备、动作、`result_sample_id`、实际记录 ID、采样数据及时间均通过校验，才报告新采集成功。结果编号须大于采集前记录编号；服务器接收时间不得早于任务下发。设备采样时间容许秒级精度误差（创建前最多 2 秒、接收后最多 5 秒），明显陈旧或超前的设备时钟会报告“无法确认”，不会改写时间戳。

设备未领取任务时，现有任务系统保持 `PENDING`。助手等待超时**不会取消服务器任务**；设备恢复后仍可能领取，页面明确说明并支持继续查询。接口提交响应丢失时，不自动重试 POST，也不声称“未创建”，提示先检查最近任务。

新增能力没有改变硬件协议、数据库结构、任务生命周期、原监控采集按钮、既有查询接口或摄像头功能。未来接入有授权的语言服务时，仅替换结构化解析层；设备校验、固定工具范围及结果校验仍须保留，模型不得产生执行成功证据。
